## 1. نتائج الاختبار الفعلي

**الإدخال (مخرج علمي):**
```python
warning = {
  "signal":        "NDMI",
  "severity":      "WARNING",
  "current_value": -0.065,
  "threshold":     -0.080,
  "confidence":    0.67,
  "days_to_breach": 128,
}
```

**الإخراج (ما يرى المهندس):**
```json
{
  "title":             "تحذير: كشف تسربات المياه — خط مياه الميناء",
  "risk_level":        "احتمال عالٍ (67%)",
  "time_to_impact":    "خلال ~128 يوم بدون تدخل",
  "recommended_action":"إرسال فريق ميداني لفحص ضغط الخط",
  "evidence":          "ارتفاع ملحوظ في رطوبة التربة"
}
```

**ما يرى المدير العام (بدون أي مصطلحات تقنية):**
```json
{
  "title":          "تحذير: كشف تسربات المياه — خط مياه الميناء",
  "evidence_summary":"ارتفاع ملحوظ في رطوبة التربة",
  "confidence":     "67%"
}
```

**اختبار التصعيد:**
```
إنذار لم يُعالَج 6 ساعات → التصعيد: مهندس → رئيس قسم
السبب: "إنذار لم يُعالَج منذ 6 ساعة — بحاجة لمتابعة"

```

## 5. محرك التصعيد

### المسار الافتراضي

```
اكتشاف الإنذار (Level 0)
    │
    │  4 ساعات بدون معالجة (WARNING/ALERT/CRITICAL)
    ↓
Level 1: رئيس القسم ← IN_APP + EMAIL
    │
    │  12 ساعة بدون حسم (ALERT/CRITICAL فقط)
    ↓
Level 2: مدير القسم ← IN_APP + EMAIL + SMS
    │
    │  24 ساعة بدون حسم (CRITICAL فقط)
    ↓
Level 3: الإدارة العليا ← IN_APP + SMS
```

### قواعد التصعيد (قابلة للتكوين لكل مهمة)

```python
EscalationRule(
    from_level       = 0,
    to_level         = 1,
    hours_to_trigger = 4.0,        # قابل للتغيير
    notify_roles     = ["SECTION_HEAD"],
    notify_channels  = ["IN_APP", "EMAIL"],
    severity_filter  = ["WARNING", "ALERT", "CRITICAL"],
)
```

### سجل التصعيد (كل تصعيد موثَّق)

```
ALT-0047BFBB | تاريخ التصعيد | السبب | من → إلى | قنوات الإشعار
─────────────────────────────────────────────────────────────────

2026-07-10 02:30  | لم يُحسَم 12 ساعة  | L1→L2 | IN_APP+EMAIL+SMS
```

## 6. نظام الإشعارات

### القنوات المدعومة

| القناة | الاستخدام | الإعداد |
|--------|-----------|---------|
| `IN_APP` | كل المستخدمين — فوري | افتراضي دائماً |
| `EMAIL` | المديرون — بعد ساعة | SMTP config |
| `SMS` | حالات CRITICAL فقط | API مزود SMS |
| `PUSH` | التطبيق الموبايل | Firebase FCM |

### كل Mission تحدد جمهورها

```python
# في تكوين Mission
notification_config = {
  "WATCH":    {"channels": ["IN_APP"],           "roles": ["ENGINEER"]},
  "WARNING":  {"channels": ["IN_APP", "EMAIL"],   "roles": ["ENGINEER", "SECTION_HEAD"]},
  "ALERT":    {"channels": ["IN_APP", "EMAIL", "SMS"], "roles": ["DEPT_MANAGER", "ENGINEER"]},
  "CRITICAL": {"channels": ["IN_APP", "SMS"],    "roles": ["ALL"]},
}
```


## 7. التطبيق الميداني

### متطلبات تقنية

```
Framework:    Flutter (يدعم iOS + Android من codebase واحد)
Offline:      SQLite محلي — يُزامَن عند الاتصال
الخريطة:     OpenLayers Offline Tiles (مُحمَّلة مسبقاً للمنطقة)
الصور:       تُضغَط محلياً → تُحمَّل عند WiFi
GPS:          يُسجَّل مع كل صورة وكل بند في قائمة التحقق
Push:         Firebase Cloud Messaging
```

### سير العمل الميداني

```
1. استقبال إشعار Push للمهمة الجديدة
   ↓
2. رؤية تفاصيل الهدف (الخريطة، التاريخ، الصور السابقة)
   ↓
3. الذهاب للموقع (التنقل عبر الخريطة المدمجة)
   ↓
4. تسجيل الوصول (GPS تلقائي)
   ↓
5. إتمام قائمة التحقق بنداً بنداً
   ↓
6. رفع الصور (قبل + بعد + أي ضرر)
   ↓
7. تسجيل النتيجة (تأكيد/نفي الشذوذ + الملاحظات)
   ↓
```

## 10. التحقق الميداني → MINERVA

### حلقة التحقق الكاملة

```
MINERVA يُولّد إنذاراً (بيانات أقمار صناعية)
     ↓
فني يزور الموقع (بيانات ميدانية حقيقية)
     ↓
النتيجة: "الشذوذ مؤكد / إنذار كاذب"
     ↓
Ground Truth يُرفَع تلقائياً لـ MINERVA
     ↓
┌─────────────────────────────────────────┐
│  MINERVA تتعلم:                         │
│  • إذا كان إنذاراً صحيحاً:             │
│    ← يُقوَّى النموذج لهذه الظروف       │
│    ← يُسجَّل في knowledge base         │
│    ← يُحسَّن threshold لهذا الهدف      │
│  • إذا كان إنذاراً كاذباً:             │
│    ← يُعدَّل bias_correction           │
│    ← يُرفَع حد الثقة المطلوب           │
│    ← يُحلَّل سبب الخطأ                │
└─────────────────────────────────────────┘
```

### تأثير التحقق على دقة النموذج

```
قبل التحقق الميداني:  دقة التنبؤ لهذا الهدف = 67%
بعد 10 تحققات:        دقة التنبؤ = 79%
بعد 30 تحققاً:        دقة التنبؤ = 88%

كل زيارة ميدانية = استثمار في ذكاء MINERVA
```

## 12. قاعدة البيانات

```sql
-- ── الإنذارات التشغيلية ──────────────────────────────────────────
CREATE TABLE operational_alerts (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    alert_id          TEXT UNIQUE NOT NULL,
    title             TEXT NOT NULL,
    description       TEXT,
    
    -- المصدر العلمي
    mission_id        TEXT,
    target_id         TEXT,
    mission_name      TEXT,
    target_name       TEXT,
    
    severity          TEXT NOT NULL,  -- WATCH|WARNING|ALERT|CRITICAL
    status            TEXT DEFAULT 'NEW',
    
    -- الموقع
    lat               FLOAT,
    lon               FLOAT,
    
    -- المحتوى التشغيلي
    evidence_summary     TEXT,   -- باللغة العربية البسيطة
    recommended_action   TEXT,
    risk_level_text      TEXT,
    time_to_impact_text  TEXT,
    
    -- الإدارة
    assigned_to          TEXT,
    escalation_level     INT DEFAULT 0,
    escalation_history   JSONB DEFAULT '[]',
    
    -- التتبع
    detected_at       TIMESTAMPTZ DEFAULT NOW(),
    acknowledged_at   TIMESTAMPTZ,
    acknowledged_by   TEXT,
    resolved_at       TIMESTAMPTZ,
    
    -- التقني (للمهندس)
    technical_detail  JSONB,
    
    related_alerts    TEXT[]
);

-- ── المهام الميدانية ──────────────────────────────────────────────
CREATE TABLE operational_tasks (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id      TEXT UNIQUE NOT NULL,
    alert_id     TEXT REFERENCES operational_alerts(alert_id),
    title        TEXT,
    description  TEXT,
    
    status       TEXT DEFAULT 'PENDING',
    priority     INT DEFAULT 2,
    
    assigned_to  TEXT,
    assigned_name TEXT,
    due_date     DATE,
    
    target_id    TEXT,
    target_name  TEXT,
    lat          FLOAT,
    lon          FLOAT,
    
    checklist    JSONB DEFAULT '[]',
    photos       JSONB DEFAULT '[]',
    
    -- نتيجة الزيارة
    field_finding        TEXT,
    anomaly_confirmed    BOOLEAN,
    action_taken         TEXT,
    
    created_at   TIMESTAMPTZ DEFAULT NOW(),
    completed_at TIMESTAMPTZ,
    verified_at  TIMESTAMPTZ,
    verified_by  TEXT,
    notes        TEXT
);

-- ── التحقق الميداني (Ground Truth) ───────────────────────────────
CREATE TABLE field_verifications (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    verification_id TEXT UNIQUE,
    task_id         TEXT REFERENCES operational_tasks(task_id),
    target_id       TEXT,
    verified_date   DATE,
    
    anomaly_confirmed   BOOLEAN,
    severity_observed   TEXT,
    root_cause_observed TEXT,
    
    matched_alert_type          TEXT,
    prediction_was_accurate     BOOLEAN,
    
    gps_lat FLOAT,
    gps_lon FLOAT,
    photos  TEXT[],
    
    updates_baseline BOOLEAN DEFAULT FALSE,
    notes            TEXT,
    created_at       TIMESTAMPTZ DEFAULT NOW()
);

-- ── سجل التصعيد ───────────────────────────────────────────────────
CREATE TABLE escalation_log (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    alert_id        TEXT REFERENCES operational_alerts(alert_id),
    from_level      INT,
    to_level        INT,
    triggered_at    TIMESTAMPTZ DEFAULT NOW(),
    triggered_by    TEXT,
    reason          TEXT,
    notified_users  TEXT[],
    channels_used   TEXT[]
);

-- ── سجل الإشعارات ────────────────────────────────────────────────
CREATE TABLE notification_log (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    recipient_id    TEXT,
    channel         TEXT,   -- IN_APP|EMAIL|SMS|PUSH
    subject         TEXT,
    alert_id        TEXT,
    task_id         TEXT,
    sent_at         TIMESTAMPTZ DEFAULT NOW(),
    delivered       BOOLEAN DEFAULT FALSE,
    read_at         TIMESTAMPTZ
);
```
